## 5. Migration

Migrations: `20261008135403_V121Phase1RuleGroups` (command), `20261008135407_V121Phase1RuleGroupsQuery` (read model). Up performs only `AddColumn`, `CreateTable`, `CreateIndex`, `AddForeignKey`, `AlterColumn` (only on columns added in the same migration) and `INSERT`/`UPDATE` of new columns. Nothing is dropped; `ProvisionTravelDates`, `ProvisionSeasonalPeriods`, `ProvisionDayTimeRestrictions` and the legacy root columns stay physically and are no longer mapped.

Rules of the backfill:

- Rule-group row id = provision id. A day/time restriction becomes one window with the same id and a single-bit mask.
- Dates and seasons both present → intersection; one of them present → union; none → unrestricted. Never widened.
- A merged permitted period takes the id of its oldest source row.
- Empty intersection, or a window with Start ≥ End → the provision gets a blackout `[0001-01-01, 9999-12-31]` with id = provision id (unsaleable until an author fixes it).
- Every source row has a line in `Ancillary.ProvisionRuleMigrationAudit` (source, target, outcome).

Proof on a seeded database (`V121RuleGroupMigrationAcceptanceTests`): 1000 adjacent dates → 1 period; intersection, union, quarantine and deny precedence as above; 1030 audit rows; legacy rows byte-equal before and after; Down to v12 and Up again give the same periods and audit rows.

## 7. Breaking changes for consumers

- Backoffice provision contract: `Passenger/Sales/Travel/Fare/Application` are replaced by the ten rule-group objects; `SalesEffectiveFrom/SalesDiscontinueAt` moved into `SalesRestrictions`; row routes `TravelDates`, `SeasonalPeriods`, `DayTimeRestrictions`, `BlackoutPeriods` are replaced by `TravelDate/PermittedPeriods`, `TravelDate/BlackoutPeriods`, `DayTimeApplication/Windows`.
- Definition create/update requires `ServiceDateBasis`.
- Grid columns of the provision list: `Permitted Periods`, `Blackouts`, `Day/Time`.
- Read model: new tables and columns only; legacy read tables stay but receive no new rows. AirAvail reads `ReadModel` by SQL — it was not opened or changed; its queries on the superseded tables/columns must be reviewed by its owner.

## 8. Open points

1. **`ServiceDateBasis` of the 31 dev definitions is empty.** They stay readable; Activate, Reactivate, Revise and publication of dated rules are refused (16213) until a basis is assigned. No mapping was applied.
2. **Six Active `XBAG_WEIGHT_*` provisions** are `PerItem` with `Quantity.Unit = Kilogram`, which the new matrix rejects for new publications. They were not changed.
3. **Reference existence** (airport, airline, fare family… ids against master data) is not validated; only shape and duplicates are. Unresolved, as pack 03 §4 allows.
4. **Down migration** does not rebuild v12 restrictions from windows authored after the migration.
5. Loading one provision aggregate issues about 37 split queries.
6. Concurrent edits of pricing *lines* alone (v12 code) do not version the pricing row; not changed in this phase.
