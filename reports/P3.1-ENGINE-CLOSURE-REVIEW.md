## 4. Engine

`IAncillaryShoppingEngine.ShopAsync(context, filter)` and `EvaluateSelectionAsync(context, candidateIdentity, selection)`; both only read.

1. Validate the context and the filter.
2. Five batched reads, independent of travellers, flights and candidates: Active definitions of the owner, Active provisions of those versions published for exactly the context POS, Active pricings of the filed provisions, inventory configurations (policy + typed sources of the context flights), currency decimals. The engine re-checks status, owner and POS on what the readers return.
3. Per definition, traveller and coverage scope: units (Sector = flight, Portion = portion with all its flights, Journey = all flights, Order only for a real order). Provisions of that scope in `Sequence` order; the first verdict other than "no match" decides - a match, a matching NotAvailable, or an insufficient verdict (as in the Phase 1 oracle).
4. `ProvisionEvaluation`: stage, the ten rule groups, the nine profile checks, the selection contract - three-valued (`Match`, `NoMatch`, `Insufficient`) with reason codes and missing fields.
5. `PriceAssessor`, `QuantityAssessor`, `AvailabilityAssessor` and the readiness (`NotEligible`, `Unavailable`, `NeedsVerification`, `NeedsSelection`, `NeedsQuote`, `Selectable`). `IsGuaranteed` is always false.

Ports (in `Reading/`): `IActiveAncillaryDefinitionReader`, `IActiveAncillaryProvisionReader`, `IActiveAncillaryPricingReader`, `IInventoryConfigurationReader`, with EF implementations in `Reading/Sql` (no tracking, split queries). Existing domain ports reused: `ICurrencyReference`, `IInventoryResourceReference`, `IAirportFacilityReference`, `ICountingFamilyReference`, `IFlightFlowDelegationReference`. No usage or availability evidence reader was created - no source exists.

## 8. Blocked, not run, not provable

| Item | Status | What the engine does today |
|---|---|---|
| `IInventoryResourceReference` (count / weight resources) | `BLOCKED_EXTERNAL_REFERENCE` - no authoritative source (P3-OPEN-03) | Local configuration state is reported, checked state `SourceUnavailable`, readiness `NeedsVerification` |
| `IAirportFacilityReference` (facility, airport, zone) | `BLOCKED_EXTERNAL_REFERENCE` (P3-OPEN-04) | airport-slot candidates stay `NeedsVerification` after the appointment is chosen |
| `ICountingFamilyReference` | `BLOCKED_EXTERNAL_REFERENCE` (P3-OPEN-05) | limit shown with `FamilyVerified = false` |
| `IFlightFlowDelegationReference` | `BLOCKED_EXTERNAL_REFERENCE` (P3-OPEN-06) | `DelegatedCheckRequired`, checked state `SourceUnavailable` |
| Usage ledger (P3-OPEN-02) | no source, no port | remaining quantity only from complete `VerifiedUsageEvidence` given in the context |
| Availability evidence | no connected read-only authority | `CheckedState` never `AvailableAsOf`; `IsGuaranteed` always false |
| Currency decimals (P3-OPEN-15) | data defect of the synced reference | the engine trusts the reference; an amount that does not fit it is `Incomplete` |

Not run in this phase, on purpose: any HTTP smoke, adapter test, token test, hold / confirm / release or concurrency test (P3.2 / P3.3).

Guards that exist in the engine but cannot be reached from an Active catalog, because authoring already refuses the input: a specification service window without a valid IANA zone (domain 16202), an unknown zone id on a specification (16202), fee units 6..10 at pricing publication (16305 - `PRICE_03` asserts exactly that refusal). They are defensive only and are not counted as proven engine behaviour.

Not evaluated because no approved semantics exist: baggage `TravelApplication`, `RuleDeference` and the rule-level `Weight`; flight status; `DirectionOrJourneyRef`; terminal ids. They are carried in the model and ignored by the engine.

## 9. Decisions taken inside P3.1 and questions for the Owner

Taken (each is covered by a test and can be overruled at the gate):

1. Coverage units per scope; a unit is matched only against provisions of its own scope.
2. An insufficient verdict on the lowest-sequence provision ends the evaluation of that unit (same as the Phase 1 oracle).
3. On a multi-flight unit every covered flight must satisfy every populated flight-scoped filter, date, time and lead-time rule.
4. Geography on a Portion / Journey unit is evaluated per portion (origin, destination, via of the portion); coverage country = destination country.
5. Cabin and RBD of a fare filter fall back to the flight's values when the fare fact has none.
6. Baggage: `PurchaseApplication = CheckIn` is not offered by shopping; the excess-piece tier counts the traveller's Active existing services with the same `ServiceDefinitionRef` on the unit's flights; a quantity that would leave the tier is refused.
7. Eligibility is `InsufficientContext` when a fact or a rule-bound selection (seat, appointment) is missing, and `Eligible` when only the typed form is still to be filled; the readiness then says `NeedsSelection`.
8. `EvaluateSelection` re-runs the sequence order with the selection and may land on another provision of the same definition (`ProvisionChangedBySelection`).
9. `ChildRef` of the unaccompanied-minor contract is implied by the candidate's traveller.
10. Non-sellable units appear only when the filter asks for them; another point of sale never sees anything.

Questions:

- **Q1 - definition sales dates.** `SalesEffectiveFrom` / `SalesDiscontinueOn` are `DateOnly` and no approved text says in which time zone the sale day is counted, nor whether the last day is inclusive. The engine decides only when the day is the same in every time zone (last day inclusive) and otherwise answers `SalesDateNotDetermined`. Which zone, and is the discontinue day inclusive?
- **Q2 - 29 February birthdays.** Age follows the frozen oracle formula, so such a traveller completes the year on 28 February in a non-leap year. Keep it?
- **Q3 - pet minimum age.** The selection contract has no animal-age field, so the minimum age of a pet specification or rule can only be flagged (`PetAgeNotVerified`), not checked. Add the field to the contract (a Phase 1 change) or leave it to the supplier?
- **Q4 - passenger eligibility at an exit row.** A traveller whose `VerifiedExitRowEligible` is null gets `NeedsVerification` already at `Shop`. Is that the wanted moment, or only when a seat is chosen?
- **Q5 - readiness when availability cannot be verified.** A candidate with `MustCheckAvailability` and no usable configuration, or with a blocked reference, is `NeedsVerification` (still returned). Should it rather be hidden?
