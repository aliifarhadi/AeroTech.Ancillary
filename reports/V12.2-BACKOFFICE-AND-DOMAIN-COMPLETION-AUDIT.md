## 2. Typed Backoffice surface as built

### 2.1 Service definitions

The generic `POST` / `PUT Backoffice/v1/AncillaryServiceDefinitions[/{id}]` with the nine-member `specification` envelope was **removed** (HTTP: POST -> 404, PUT -> 405). Create and edit now go through nine profile contracts. The path fixes the profile; the body carries the shared header, `variantCode`, `documentRouting` and one `specification` object of that profile only. An unknown member inside the specification is refused (HTTP 400, step N2); the request records carry the same `Disallow` annotation.

| Profile | Variants | Create | Edit draft |
|---|---|---|---|
| Baggage | A01-A06 | `POST Backoffice/v1/AncillaryServiceDefinitions/Baggage` | `PUT Backoffice/v1/AncillaryServiceDefinitions/Baggage/{serviceDefinitionId}` |
| Seat | A07-A09 | `POST Backoffice/v1/AncillaryServiceDefinitions/Seat` | `PUT Backoffice/v1/AncillaryServiceDefinitions/Seat/{serviceDefinitionId}` |
| Upgrade | A10 | `POST Backoffice/v1/AncillaryServiceDefinitions/Upgrade` | `PUT Backoffice/v1/AncillaryServiceDefinitions/Upgrade/{serviceDefinitionId}` |
| Meal | A11-A12 | `POST Backoffice/v1/AncillaryServiceDefinitions/Meal` | `PUT Backoffice/v1/AncillaryServiceDefinitions/Meal/{serviceDefinitionId}` |
| Pet | A13-A14 | `POST Backoffice/v1/AncillaryServiceDefinitions/Pet` | `PUT Backoffice/v1/AncillaryServiceDefinitions/Pet/{serviceDefinitionId}` |
| AssistedTravel | A15-A19 | `POST Backoffice/v1/AncillaryServiceDefinitions/AssistedTravel` | `PUT Backoffice/v1/AncillaryServiceDefinitions/AssistedTravel/{serviceDefinitionId}` |
| AirportService | A20-A22 | `POST Backoffice/v1/AncillaryServiceDefinitions/AirportService` | `PUT Backoffice/v1/AncillaryServiceDefinitions/AirportService/{serviceDefinitionId}` |
| Priority | A23 | `POST Backoffice/v1/AncillaryServiceDefinitions/Priority` | `PUT Backoffice/v1/AncillaryServiceDefinitions/Priority/{serviceDefinitionId}` |
| Connectivity | A24 | `POST Backoffice/v1/AncillaryServiceDefinitions/Connectivity` | `PUT Backoffice/v1/AncillaryServiceDefinitions/Connectivity/{serviceDefinitionId}` |

- Shared, unchanged: `GET .../{id}`, `GET .../Paginated`, `POST .../{id}/Activate|Suspend|Reactivate|Retire|Revise|AssignPricingUnit|AssignServiceDateBasis`.
- One validation path: the eighteen actions map into the existing `BackofficeDefine/ChangeAncillaryServiceDefinitionCommand`, the same validators, services and aggregate. No new repository, aggregate, handler family or lifecycle.
- Editing a definition through another profile contract is refused with `16219` (HTTP 409, "The service definition belongs to profile X and cannot be authored as Y"). A draft may still move to another variant of its own profile until a version is published.
- OpenAPI (`/swagger/v1/swagger.json` of the running host): 18 typed operations, one tag per profile (`Backoffice Baggage` ... `Backoffice Connectivity`), 18 request schemas (`<Profile>SpecificationInputDefineServiceDefinitionRequest`, `...ChangeServiceDefinitionRequest`), no generic path. **Not done:** embedded request examples in the OpenAPI document - the Swagger setup lives in `Framework/` (not editable here); the usable examples are in section 2.4.

### 2.2 Provision

- Shared endpoints and the one-POS invariant are unchanged. Three typed partial-update endpoints were added beside the ten existing rule-group endpoints, same use-case pattern, draft only:
  - `PUT Backoffice/v1/AncillaryProvisions/{provisionId}/PetRule`
  - `PUT Backoffice/v1/AncillaryProvisions/{provisionId}/AssistedTravelRule`
  - `PUT Backoffice/v1/AncillaryProvisions/{provisionId}/AirportServiceRule`
- A rule outside the profile of the definition is refused at once with `16321` (HTTP 409); sending `null` removes the rule; an Active provision refuses the edit with `16303`.
- Provision detail now carries `profile`, `variantCode` and `applicableRuleSections`: the six shared sections, `FlightApplication` + `FareApplication` only for flight-dated products, and exactly the profile section (`BaggageApplication`, `SeatApplication`, `PetRule`, `AssistedTravelRule`, `AirportServiceRule`). A form renders only those.

### 2.3 Pricing and inventory

Unchanged shared endpoints: one pricing model (rates, Money, tax treatment, fee unit) with the provision price origin Filed / ExternalQuote / Free / NotAvailable; one policy endpoint with authority, typed Count / Weight / Slot consumption and usage limits. No per-profile price or stock table exists.
