# P3.2B - Surface contracts and DTO traceability (STEP 3)

Every example below is cut from the golden files `tests/AeroTech.Ancillary.Shopping.Tests/Fixtures/Golden/*.json`. They are produced by the compiled DTOs through the host's serializer settings (web defaults, `JsonStringEnumConverter`, `LongToStringJsonConverter`, `NullableLongToStringJsonConverter` of `Framework.Presentation`) from the sanitized real flight-offer capture `Fixtures/Wire/flight-offer-details.json` and the lab catalog. Prices are test rates, not airline prices. `<offer-id>` replaces the sanitized offer id.

## 1. Routes, policies, inbound contracts

| Surface | Route (all `POST`) | Policy | Inbound type | Body |
|---|---|---|---|---|
| Backoffice | `/Backoffice/v1/AncillaryOffers` | `SurfaceAuthorization.Backoffice` | `BackofficeGetAncillaryOffersQuery` | `{ offerId, options? }` |
| | `/Backoffice/v1/AncillaryOffers/Details` | | `BackofficeGetAncillaryOfferDetailQuery` | `{ offerId, offerItemRef, options? }` |
| | `/Backoffice/v1/AncillaryOffers/Selections/Evaluate` | | `BackofficeEvaluateSelectionQuery` | `{ offerId, offerItemRef, selection, options? }` |
| | `/Backoffice/v1/AncillaryOffers/SeatMaps` | | `BackofficeGetSeatMapQuery` | `{ offerId, offerItemRef, options? }` |
| Agency API | `/Api/v1/AncillaryOffers` (+ `/Details`, `/Selections/Evaluate`, `/SeatMaps`) | `SurfaceAuthorization.Ota` | `ApiGetAncillaryOffersQuery`, `ApiGetAncillaryOfferDetailQuery`, `ApiEvaluateSelectionQuery`, `ApiGetSeatMapQuery` | `{ offerId }`, `{ offerId, offerItemRef }`, `{ offerId, offerItemRef, selection }` |
| Agency panel | `/OtaPanel/v1/AncillaryOffers` (+ the same three) | `SurfaceAuthorization.OtaPanel` | `OtaPanelGetAncillaryOffersQuery`, ... | as the API |

`options` = `customerId: string?`, `countryId: long?`, `pointOfSaleId: long?`, `salesDate: DateTimeOffset?`, `preferredCurrencyId: int?` (unchanged from P3.2A-R1). The agency requests have no other member; unknown members of a body are ignored by the serializer and no resolver reads the body (`P32B_AGY_02`). `selection` is one typed class per surface with the 37 members of the engine's `AncillarySelection`; there is no dictionary and no "verified" member a caller could assert.

Twelve distinct inbound types, three controllers, three policies: pinned by `P32B_SRF_05`. The policies are enforced by the framework before the action runs, so a token of another surface never reaches the provider call.

## 2. Sales scope per surface

| Fact | Backoffice | Agency API and panel (one shared `AgencySalesScopeService`) |
|---|---|---|
| caller | airline context with airline user and office claims, else 403 / 16809 | `travel_agency_id` claim, else 403 / 16809 |
| owner airline | operator home airline | operator home airline |
| channel | `BackOffice` | `PartnerAPI` (AirAvail's `API`, by name) |
| points of sale | `options.pointOfSaleId` as the only id; otherwise the eligible set for (country option, office claim, channel) | the eligible set for (`X-Country`, first `travel_agency_office_id` claim or 0, channel) |
| customer | `options.customerId` when numeric | `customer_id` claim |
| currency | `options.preferredCurrencyId`, 0 = none -> the flight offer's currency | 70 (`AgencySalesPolicy.CurrencyId`, the one place that holds AirAvail's current constant) |
| sales instant | `options.salesDate`, else clock | clock |
| eligibility reference not connected | 409 / 16808 `POS_CONTEXT_UNRESOLVED: BLOCKED_EXTERNAL_REFERENCE ...` | the same; **always**, because these surfaces cannot name a point of sale |
| eligible set empty | 200, no offers, diagnostic `NO_AUTHORIZED_POINT_OF_SALE` | 200, `responseStatus: NoApplicableOffer` / empty groups |

Tests: `PARITY_BO_01..04`, `CT_04`, `P32B_AGY_01`, `P32B_POS_01`.

## 3. OfferItemRef

`offerItemRef` = base64url of SHA-256 over (channel name, owner airline, point of sale, offer id, definition version, provision, pricing revision, coverage scope, traveller, coverage unit). It carries no readable id and no secret. It is never decoded: `Details`, `Selections/Evaluate` and `SeatMaps` shop the same offer again under the caller's own scope and look for the item with that ref; anything else is 404 / 16811 `OFFER_ITEM_NOT_FOUND` (a ref of another surface, another point of sale, another airline, a raw provision id, an altered ref, a ref whose pricing was replaced), a blank ref is 422 / 16810 (`P32B_REF_01`). It is a pointer for re-evaluation, not an offer id, hold, price guarantee or purchase token; `canPurchase` is `false` everywhere.

## 4. Agency API - field by field

Shape taken from the NDC 21.3 ServiceList relationships named by the pack (data lists, a-la-carte offer, offer items with passenger and segment references, separate service definitions). It is this service's own JSON, not IATA NDC XML and not certified.

| API member | Source (canonical) | NDC 21.3 relation it follows | Difference |
|---|---|---|---|
| `sourceOfferId` | `FlightOffer.OfferId` | Offer context of ServiceListRQ | the flight offer id, not an ancillary offer id |
| `currency.{id, code}` | target currency of the scope; code only when it is the flight offer's own (verified) | - | id is the platform id |
| `dataLists.passengers[].{passengerRef, ptc}` | flight-offer tickets | `PaxList/Pax` | no personal data |
| `dataLists.paxSegments[]` | flight-offer bounds and flights; `segmentRef` = `<bound>:F<n>`, `journeyRef` = bound | `PaxSegmentList`, `PaxJourneyList` | ids of airports / airlines are platform ids |
| `dataLists.serviceDefinitions[]` | engine candidate: ref, name, description, profile (`category`), variant, service type and sub code, RFIC / RFISC, document type, booking method, SSR | `ServiceDefinitionList/ServiceDefinition` | one entry per `serviceDefinitionRef`, deduplicated |
| `aLaCarteOffers[]` | one per authorized point of sale that has an offered item | `ALaCarteOffer` | the point of sale itself is not shown |
| `offerItems[].offerItemRef` | section 3 | `OfferItemID` | read-only pointer, not bookable |
| `offerItems[].serviceDefinitionRef` | candidate | `ServiceDefinitionRefID` | |
| `offerItems[].eligibility.{coverageScope, passengerRefs, segmentRefs, journeyRefs}` | candidate coverage | `Eligibility/PaxRefID`, `FlightAssociations` | |
| `offerItems[].pricing.{origin, status, unit}` | `PriceAssessment` | `UnitPrice` | status explicit |
| `pricing.unitPrice`, `pricing.base` | `CompleteUnitTotal`, `BaseAmount` with the rate currency; `null` for quote / free / incomplete | `UnitPrice/TotalAmount`, `BaseAmount` | never 0 for "unknown" |
| `pricing.taxes`, `includedTaxes`, `additionalFees`, `orderLevelFees` | added tax lines, included tax lines, item fees, fees that are not per item (with `appliesPer`) | `TaxSummary`, `Fee` | order-level fees are listed outside the unit price |
| `pricing.totalPrice`, `totalComplete` | `RequestedQuantityTotal` (only after a selection), `IsOrderLevelTotalComplete` | OfferPrice total | `null` on search |
| `quantity.{unit, min, max}` | `QuantityAssessment` | - | |
| `selectionRequirements[]` | selection contract of the definition | - | |
| `availability.{state, guaranteed, requiresCheckAtReserve}` | `AvailabilityAssessment` | - | never "available" without evidence |
| `confirmationRequirement`, `readiness`, `canPurchase`, `reasons[]` | candidate | - | reason codes only, no field paths |
| `withheldItemCount` | candidates that are not Selectable / NeedsSelection / NeedsQuote | - | count only |
| `responseStatus` | `NeedsSelectionOrRecheck` when an item is offered, else `NoApplicableOffer` | - | |

Not on the API, by test (`P32B_SRF_02`): provision id, pricing revision and rate ids, definition version id, supplier id, point of sale, owner airline, diagnostics, missing context fields.

## 5. Backoffice and panel

| | Backoffice | Agency panel |
|---|---|---|
| purpose | operator investigation | sales screen |
| top level | `offerId`, `evaluatedAtUtc`, `currency`, `flightOffer`, `scope`, `journey`, `travellers`, `categories`, `offers`, `blockedOffers`, `diagnostics`, `completeness` | `offerId`, `currencyId`, `currencyCode`, `travellerGroups[]`, `blockedCount` |
| grouping | flat lists of candidates | traveller -> flight -> services; a service that covers several flights appears once, under its first covered flight, with `coveredFlightRefs` |
| enums | `{ value, name, title }` (Backoffice convention) | names |
| internal data | candidate identity (definition version, provision, pricing revision), point of sale per offer, diagnostics with missing fields, blocked candidates in full | none of these |
| included baggage | per traveller and flight, with fare facts | per flight group, checked and cabin |
| price | all lines | `unitPrice`, `priceStatus`, `priceUnit`, `orderLevelFees`; the full breakdown is in the panel detail |
| status | `offerReadiness` + `displayState` | `displayStatus` (`AvailableForSelection`, `NeedsInput`, `QuoteRequired`) + `requiresRecheck` |

Backoffice compatibility: route and payload of P3.2.A are kept. Additions only: `offers[].offerItemRef`, `offers[].pointOfSaleId`, `scope.pointOfSaleIds`; one type change: `scope.pointOfSaleId` is `null` when the scope holds more or fewer than one point of sale (it was always one id). The existing Backoffice tests (`CT-xx`, `PARITY-BO`, `PRICE`, `INV`) pass unchanged in their assertions on the payload.

## 6. Same decision on three contracts

`P32B_SRF_01`: one snapshot mapped three times - for every item the unit amount, currency, price status, readiness, covered flights and order-level fees are equal; the Api and Backoffice top-level types share only the member `currency`, and the panel type has its own five members. `P32B_SRF_04`: a Backoffice scope and an agency scope with the same owner, point of sale, customer, currency and instant give the same candidate identities, readiness and amounts; only the refs differ. No mapper computes a price: they copy members of `PriceAssessment`.

## 7. Golden files and OpenAPI

| File | Content |
|---|---|
| `backoffice-offers.json`, `api-offers.json`, `otapanel-offers.json` | search of the same lab catalog (A01, A07, A24 offered; A10 blocked) on the real capture, two travellers, two bounds |
| `*-detail.json` | details of the A01 item |
| `*-selection.json` | selection of quantity 2 for that item |

`P32B_GOLD_01` compares the serializer output with the files on every run (regenerate with the environment variable `P32B_WRITE_GOLDEN=1`).

OpenAPI (read from `/swagger/v1/swagger.json` of the running host on 2026-10-11): twelve `AncillaryOffers` operations under the tags `Backoffice`, `Api` and `OtaPanel`, each with its own request schema (`BackofficeGetAncillaryOffersQuery` = `offerId`, `options`; `ApiGetAncillaryOffersQuery` = `offerId` only; ... twelve schemas, plus the three selection input schemas and `BackofficeAncillaryOfferOptions`). The document states only a `200` response without a body schema for every operation. Embedded examples and response schemas were **not** added: the Swagger configuration and the response envelope filter live in `Framework/`, which this repository does not change, and the actions return `IActionResult` like every other controller here. The golden files are the examples.
