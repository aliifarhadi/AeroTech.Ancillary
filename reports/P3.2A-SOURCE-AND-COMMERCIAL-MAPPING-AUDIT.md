## 2. Producer contract - AirAvail `POST Service/v1/FlightOffers/Details`

`PRODUCER_SOURCE_VERIFIED` (`ServiceController`, `ServiceGetFlightOffersDetailRequest`, `ServiceFlightOfferDetailService`, `ServiceFlightOfferDetailMapper`, `ServiceFlightOfferDetailDto`, `JourneyOfferIdCodec`) and `LIVE_OBSERVED` on staging.

- Request body `{ "offerId": string }`. `ServiceBaseController` carries no `[Authorize]`; the staging call succeeded without a token.
- The service refuses an offer id that does not decode or has no third (commercial) section: business error `OfferMustBePricedBeforeOrdering`. Otherwise it **re-prices** through `OfferPricePipeline.PriceAsync` with the decoded channel, customer, country, currency and sales date, and maps the graph.
- `OfferId` of the answer = the requested string (`SearchRequestId = offerId` in the pipeline). `PricedAt` = the decoded `SalesDate` (not the time of this call). `LastTicketingDate` = `PricedAt` + the smallest `TicketingRestrictionMinutes`, or null. No offer expiry exists in the contract.
- Envelope `BaseResult<T>`: `{ "data": ..., "errors": [{ code, title, detail }] }`.

Live observations (staging, 2026-10-11, no token, base `https://aerotech-airavail.dotair.stg.agidp.ir/service/`):

| Request | HTTP | Body |
|---|---|---|
| priced three-section offer id (1 ADT + 1 CHD, round trip, supplied by the Owner) | 200 | full `data`, 13.8 KB, `errors: null` |
| two-section (search) offer id | 400 | `{"errors":[{"code":6026,"title":"Offer must be priced before ordering.","detail":null}]}` |
| text that is not an offer id; empty string | 400 | same 6026 |
| well-formed three-section id with capacity ids that do not exist | **200** | `data` with `airTransports: []`, `tickets: []`, amounts 0, `currencyCode: "70"` |

The last row matters: the producer answers 200 with an empty journey. The consumer must treat "no bound or no ticket" as an offer that was not found, never as "no ancillaries".

Wire facts seen in the real 200 answer: camelCase; enums are **numbers** (`"direction": 1`, `"category": 0`, stop type); the members annotated `WriteAsString` arrive as strings (`originAirportId` of a bound, `flightId`, `flightCapacityId`, `legId`, `airFareId`, fare-component `rbdId`); `baggageUnit` is the enum name (`"Kg"`); `passengerTypeCode` is the enum name (`"ADT"`, `"CHD"`); `fareType` is a name (`"Public"`); `kind` is a name (`"OneWay"`).

### Producer versus the Ordering consumer wire

`CONSUMER_SOURCE_VERIFIED` (`OfferProvider`, `FlightOfferDetailResponse`, `OfferResponseMapper`, `OfferReader`, `DependencyInjection`). Ordering posts `v1/FlightOffers/Details` relative to `Offer:BaseUrl` (the Owner's development value ends with `/service/`), with `PropertyNameCaseInsensitive`, `AllowReadingFromString` and `JsonStringEnumConverter`, and reads `OfferEnvelope<T> { Data, Errors }`.

| Member | Producer | Ordering consumer | Decision for the Ancillary wire type |
|---|---|---|---|
| `PricedAt`, `CurrencyCode`, `JourneyType`, offer / ticket / coupon `BaseAmount`, `ChargeAmount`, `TotalAmount` | present | absent | read them (source summary of the response) |
| bound `Direction` | `OfferBoundDirection` (1 Outbound, 2 Inbound), numeric on the wire | absent | read as a local enum |
| airport, airline, aircraft, cabin ids | `int` | `long` | `int`, as the producer and as the Ancillary context |
| flight `Stop`; coupon `CouponId`, `Sequence`; fare component `Origin`, `Destination`, `CabinClassId`, `RbdId`, `TicketingRestrictionMinutes`; pricing line `IsPercentage` | present | absent | read what the mapping needs (`CabinClassId`, `RbdId`) |
| baggage weights | `int` | `decimal` | `decimal` on read (accepts both) |
| `BaggageUnit` | `WeightUnit.ToString()`; `""` when no fare line covers the coupon; `"0"` when the fare line carries the default enum value | `string?`, blank = no allowance | only `Kg` / `Lbs` are verified; anything else = unknown allowance |

`OfferBoundDirection`, `ServiceOfferPricingCategory` do not exist in this repository's copy of `Contracts/AeroTech.Messages` (only `Ancillary/` is writable there), so the consumer wire types declare their own local equivalents, as Ordering does with `OfferPricingCategory`.

Join rules taken from the producer mapper: one ticket per passenger, one coupon per flight segment (`CouponId = {travellerRef}-{flightId}`); a coupon's fare line has `Category = Fare` and `Reference = AirFareId`; legs are itinerary detail only; `PricingUnits[].CoveredBoundOfferIds` point at `AirTransports[].BoundOfferId`. Ordering's `ResolveCouponAirFareId` falls back to the first fare component of the bound when the coupon has no fare reference; the Ancillary mapper will not do that - a coupon without exactly one resolvable fare has unknown fare facts.

## 3. The commercial model of AirAvail, per surface

`PRODUCER_SOURCE_VERIFIED` (`BackofficeSearchFlightOffersService`, `IbeSearchFlightOffersService`, `OtaSearchFlightOffersService`, `PointOfSaleEligibilityService`, `FareVisibilityPolicy`, the Backoffice request types).

| Surface | Channel | Identity used | Point-of-sale input | Other commercial input |
|---|---|---|---|---|
| Backoffice (`FlightOffers/Grids`, `FlightAvailability/Price`) | `BackOffice` | airline user id -> all airline offices of that user (Core); no user or no office = "invalid POS" | request `options.pointOfSaleId` when present -> the allowed set is exactly that id (not validated); otherwise the set resolved by eligibility from `options.countryId`, the office ids and the channel | `options.customerId`, `options.salesDate` (else the clock), `options.preferredCurrencyId` (else 0) |
| IBE | `IBE` | identity country and customer | eligibility from country and channel | sales date = clock |
| OTA / partner API | `API` | travel agency id (required), first travel agency office, customer, country | eligibility from country, agency office and channel | currency fixed to 70 in source (marked TODO there) |

Eligibility (`PointOfSaleEligibilityService`): a point of sale is allowed when **any** of its conditions matches; a condition matches when each of its four optional dimensions (country, airline office, travel agency office, channel) matches with its include / exclude flag; a point of sale without conditions is never allowed. The result is a **set**. A fare without a point of sale is visible to everyone; a fare with one is visible only when that id is in the allowed set.

Consequences for Ancillary:

1. A point of sale is not unique per sale: AirAvail itself works with an allowed set, or with one id the Backoffice operator names.
2. The priced offer id carries channel, customer, country, currency and sales date, but **no point of sale** and no office; `FlightOffers/Details` does not echo any of them. The offer id is plain text, not a signed token; it proves nothing about the caller.
3. The data needed for eligibility (AirPrice `PointOfSale` and its conditions) is reachable only through AirPrice Backoffice routes (`Backoffice/v1/PointOfSales...`) and through the AirPrice database that AirAvail reads directly. There is no service-to-service route, and the three `PointOfSale*` integration events in `AeroTech.Messages` carry no conditions. `EXTERNAL_BLOCKED` for Ancillary.
4. Staging has three points of sale (ids `1`, `1470355450238074880`, `1525580011535335424`); only id 1 has conditions. Every provision of the development catalog of this repository (24 rows) was authored with point of sale `9200000000000001`, which is an airline office id, not an AirPrice point-of-sale id. Authoring never validated the id.

**Owner ruling (2026-10-11, asked with this evidence):** "do exactly the model AirAvail implemented at the input of its FlightOffers endpoints; each surface has its own model". For this Backoffice endpoint that means the request is `offerId` plus the same optional `options` object as AirAvail Backoffice (`customerId`, `countryId`, `pointOfSaleId`, `salesDate`, `preferredCurrencyId`), channel `BackOffice`, the airline caller's office, and the same point-of-sale rule: the named id, else eligibility. This overrides pack 02 section 1 ("exactly one input") and the pack stop condition about a point of sale in the request; it is recorded in the closure report as an Owner decision.

What stays blocked: eligibility without a named point of sale has no source in Ancillary (item 3). The endpoint will use a port for it, answer `POS_CONTEXT_UNRESOLVED` while that port is not connected, and never fall back to a default.

## 4. Caller and owner

- `SurfaceAuthorization.Backoffice` = authenticated, claim `authz_surface = backoffice`, scope of the Backoffice surface. `ICallerContext` gives context type, airline user id and one airline office id (`airline_office_id` claim); it has no point of sale.
- Owner airline: `IOperatorAirlineResolver.FindHomeAirlineIdAsync` (ReferenceData operator settings), the same source the inventory use cases use. The engine evaluates only the owner's catalog; flights whose operating or marketing airline differs are passed as facts and are matched only by provisions that name them.

## 6. True blockers going into implementation

1. Point-of-sale eligibility source (section 3) - `EXTERNAL_BLOCKED`; the named-id path works.
2. Airport IANA time zone - `EXTERNAL_BLOCKED`.
3. Numeric fare family id - `EXTERNAL_BLOCKED`.
4. Currency decimal places of the synced reference (known defect, P3-OPEN-15) - prices that do not fit the reference scale stay incomplete.
5. No commercial identity can be matched between the offer id and the caller from the producer answer; the endpoint relies on Backoffice authorization and the owner catalog only, and says so.

The legacy AirAvail routes `Service/v1/AncillaryOffers` and `AncillaryOffers/Details` are not called and not read by this work.
