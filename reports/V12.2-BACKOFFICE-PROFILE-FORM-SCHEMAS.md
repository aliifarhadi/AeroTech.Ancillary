# AeroTech Ancillary v12.2 - Backoffice form schema and read DTO for the nine profiles

Generated from `src/AeroTech.Ancillary.Application/AncillaryServiceDefinitionAggregate/Commands/DefineAncillaryServiceDefinition/ServiceSpecificationInputs.cs` (the request records the API binds) and the enum files in `Contracts/AeroTech.Messages/Ancillary/Enums/`. No frontend code is part of this delivery.

## 1. Common contract

- Write: one contract per profile - `POST /Backoffice/v1/AncillaryServiceDefinitions/{Profile}` and `PUT /Backoffice/v1/AncillaryServiceDefinitions/{Profile}/{id}` with `{Profile}` = Baggage, Seat, Upgrade, Meal, Pet, AssistedTravel, AirportService, Priority or Connectivity. The generic POST / PUT no longer exists.
- The path fixes the profile. Body = the shared header fields + `variantCode` (string, a variant of that profile), `documentRouting` (enum `DocumentRouting`) and `specification` = the object of section 2 for that profile, sent directly (no envelope, no `profile` field).
- A variant of another profile is refused with `16202` (HTTP 422); a missing `specification` with `16216`; editing a definition through the route of another profile with `16219` (HTTP 409).
- Every specification object is annotated `JsonUnmappedMemberHandling.Disallow`, so a misspelled or foreign JSON member is refused instead of being ignored (observed in the HTTP smoke: HTTP 400, like an enum value that is not a member).
- Enums travel as their member name in requests (for example `"Preferred"`); ids of type `long` travel as strings; decimals are plain JSON numbers with at most 3 decimals for kg/cm values.
- Shape errors (enum membership, lengths) are refused by the request validators. Business rules (the "Rule" column) are refused by the domain with code `16202` (HTTP 422) and the field name `<Specification>.<Field>`.
- `documentRouting`: `Emd` needs `document.type` EmdAssociated or EmdStandalone; `NoAncillaryDocument` and `TicketOrExchange` need `document.type = None`; `TicketOrExchange` is only valid when the seat/upgrade specification declares the external ticket action.
- `profile` and `variantCode` cannot change once a version of the same service reference has been published (code `16217`, HTTP 409).
- Read: `GET /Backoffice/v1/AncillaryServiceDefinitions/{id}` returns the same members inside `data.specification` with three differences: enums are `{ "value", "name", "title" }`, lists are always arrays, and three extra header fields exist: `variantName`, `selectionContract` and `profile`/`documentRouting` as enum objects. The list endpoint has two new grid columns: `Profile` and `Variant`.
- `selectionContract` (read only, derived from variant + specification, never stored): `{ "kind", "zeroQuantityMeansNoSelection", "fields": [{ "name", "type", "required" }] }`. It describes what the shopper must supply in Phase 3; no shopper value is stored in the catalog.

### Form tabs

`General` (existing header + profile + variant + document routing) - `Product-specific` (the object of section 2) - `Eligibility & POS` (provision: exactly one point of sale) - `Pricing` (price origin, rates, tax treatment) - `Capacity` (inventory policy, usage limits) - `Review & Publish`.
