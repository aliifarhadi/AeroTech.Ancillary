## 8. Decisions taken inside the pack's rules (for review)

1. Port and model live in the Application project (Query already references Providers, so Query could not host them without a cycle).
2. Zero eligible points of sale = 200 with an explicit diagnostic; an unconnected reference = 409 / 16808 on every surface.
3. `offerItemRef` is a hash resolved by re-shopping; it includes the pricing revision, so a price change makes old refs stale (404).
4. The agency API omits candidates that need verification and reports their count; the panel reports `blockedCount`; Backoffice lists them.
5. Agency callers need only the `travel_agency_id` claim (as AirAvail); a missing office claim becomes office 0 in the eligibility query (as AirAvail's `FirstOrDefault`).
6. Currency 70 for agency surfaces sits in one constant (`AgencySalesPolicy.CurrencyId`), mirroring AirAvail's current code.
7. `SeatMaps` takes `{offerId, offerItemRef}` and is refused (422) for an item that is not a seat product.
8. Backoffice payload additions: `offers[].offerItemRef`, `offers[].pointOfSaleId`, `scope.pointOfSaleIds`; `scope.pointOfSaleId` is null unless exactly one point of sale is in scope.
