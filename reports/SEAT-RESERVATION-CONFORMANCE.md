## 2. Behaviour

- **Seat check (facade).** Each id is decoded (`travellerRef|flightId|pricingId|SEAT`). The seat engine runs again with the facts Ordering sent: traveller (PTC, DOB, order traveller id), flight, fare (fare family is looked up from `airFareId`), point of sale, currency, stage (pre-order, or post-ticketed when `ticketedAtUtc` is set). The seat's characteristics come from the AirInfo aircraft map. The seat must come out `AVAILABLE` and priced by the same `pricingId`. Otherwise the request fails with 422 / 16415 and names the seat and the reason (for example `PriceChanged`, `SeatSelectionNotOffered`). Occupancy is not checked here: the physical seat is FlightFlow's hold, which Ordering takes first.
- **One write path.** The facade turns the verified seats into units (quantity 1, Sector, the flight id) and calls the existing `HoldAncillaryServicesService`: all seats are saved in one transaction or none are; the same key and the same seats replay the same hold; the same key with another seat is 409 / 16403; an order service that already has a live unit is 409 / 16406; one seat of a flight cannot be held twice in one hold.
- **Lock.** A new hold runs under a distributed lock on `ancillary-hold:{orderId}` (`IDistributedLock`, as Ordering's `ReservationLock`); a busy order is 409 / 16416. A replay is answered before the lock.
- **States (FlightFlow guards).** Confirm: Held → Confirmed, repeat is a no-op. Release: Held → Released, repeat is a no-op. Cancel: Confirmed → Cancelled with the reason on every unit, repeat is a no-op. Any other move is refused: expired 16407, confirmed 16411, released 16412, cancelled 16413, not confirmed 16414. Whole hold only (no partial cancel).
- **Expiry.** The status stays lazy (a past `ExpiresAt` reads as Expired at once). `AncillaryHoldExpiryPoller` (a BackgroundService beside the existing pollers) also writes Expired on the hold and its units, every `Holds:ExpiryPollIntervalSeconds`, at most `Holds:ExpiryBatchSize` holds per run. `requestedExpiresAt` is required on the seat route.
- **Settings (fail fast when missing).** `Holds:LockExpirySeconds` 30, `Holds:ExpiryPollIntervalSeconds` 60, `Holds:ExpiryBatchSize` 200 in `appsettings.json`.

## 6a. Correction 2026-10-22 (Owner's request with `ticketedAtUtc` was refused)

- Cause: a ticketed order puts the engine in the post-ticketed stage, where every traveller and flight needs the coupon fact `CouponOpenForUse`. The seat input had no such field, so the category was unverified and the seat blocked. The answer named only `SeatSelectionNotOffered` because a blocked seat carried no reason.
- Fix 1: seat input gains `couponOpenForUse` (bool?). It is required on every seat when `ticketedAtUtc` is set, so a missing value is a 400 validation error, and it is passed to the engine as the coupon fact.
- Fix 2: `SeatPricing` now carries the reason codes of the category that blocked the seat. A refusal names them, for example `CouponNotOpenForUse`. When no category prices the seat, the reason stays `SeatSelectionNotOffered`. The SeatMaps DTO is unchanged.
- Note: when every provision of the category refuses, the reasons come from the first refusing provision. On the dev catalog that can add `FareFamilyNotAllowed` next to the real reason.
- Proof: clean build 0 errors; Domain 264/264, Shopping 368/368 (new VER_06), Application 232/232 (new SEAT_A08), each equal to its listed count. The freeze hash was re-pinned to `BCB3AE2E…7269`. Live on my side host, with your request:
  - as sent → 400 (`couponOpenForUse` missing);
  - with a closed coupon → 422 / 16415 naming `CouponNotOpenForUse`;
  - with an open coupon → 201 Held, 7A, the pricing from the id (released afterwards).
- The open-coupon call first hit 409 / 16406 because order service 123 is held live by your own hold with key `345` (order 1001). That is correct; I repeated the call with another order service.
