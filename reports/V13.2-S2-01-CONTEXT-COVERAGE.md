## 3. What was built

### T1/T2 — producer fields retained (Providers + Application)

- Wire (`Providers/Offer/Wire`): `OfferFlight.FlightCapacityId`; coupon `IsRefundable/IsChangeable/IsUpgradable`; `OfferPricingLine` + Name, Code, Amount, CurrencyId, IsPercentage, EquivalentAmount, EquivalentCurrencyId, RateOfExchangePeriodId; response + `OrderCharges`, `RatesOfExchange` (new `OfferRateOfExchange.cs`). The existing route `POST /Service/v1/FlightOffers/Details` and its `{offerId}` request are untouched.
- Model (`Application/FlightOffers`): `FlightOfferFlight.FlightCapacityId` (long, separate from `FlightId`); coupon flags + `PriceLines`; offer `OrderCharges` + `RatesOfExchange`; new records `FlightOfferPriceLine`, `FlightOfferRateOfExchange` (one type per file); new enum `FlightOfferPriceCategory` in `Contracts/AeroTech.Messages/Ancillary/Enums` (1-based, Display, mapped by name from the 0-based wire category).
- Mapper: refuses `FlightCapacityId <= 0` and inconsistent rates of exchange with the existing 16807 `FlightOfferIsInconsistent` (502); `AirFareIds` derivation unchanged.

### T3 — evaluation clock, TTL, fingerprint (Query)

- `FlightOfferShoppingSource` now takes `IClock` + `FlightOfferShoppingOptions` (new file, `From(configuration)` throws when `Shopping:SourceContextTtl` is missing or not a positive TimeSpan; registered as a singleton in `AddQuery`).
- `FlightOfferShoppingContextMapper.Map` takes `evaluatedAtUtc`, `validUntilUtc`, `sourceVersion`: `EvaluatedAtUtc` = server clock (never `PricedAt`), `SourceIdentity.ValidUntilUtc` = clock + TTL (never `LastTicketingDate`), `TrustedSourceVersion` = fingerprint. `PricedAt` stays on the `FlightOffer` model as a source fact.
- New `FlightOfferFingerprint.Of(offer)`: SHA-256 over trusted source fields only — offer id, priced-at, currency, the three amounts, per flight (id, capacity id, version, aircraft, cabin, RBD, booking class, airports, times), fare components (basis / family / type), tickets (ref, PTC).
- `OfferItemRef.Of` gained the `sourceVersion` hash input (ruling 2). `OfSeat` is unchanged — SeatMap composition stays as is until S2-05.

### T4 — beneficiaryless Order coverage (Shopping engine)

- `CoveragePlanner`: `Order` scope now plans exactly ONE unit with no traveller (`CoverageRef = "ORDER"`, all flights and portions) when the source is a priced Offer, or an Order with `OrderId > 0`. Sector/Portion/Journey still need a traveller.
- `EvaluationUnit.Traveller` is nullable; `FareOf`/`BaggageOf` answer null and `ActiveServices` empty without a traveller; new `TravellerRef` ("" when none).
- `ShopAsync`: non-Order scopes run per traveller exactly as before (output order unchanged); the Order scope runs once per definition after the traveller loop. A traveller-filtered query (`filter.TravellerRefs`) plans no Order unit (my choice — a per-traveller question has no order-level answer; say so if it should include them).
- `EvaluateSelectionAsync` accepts the Order candidate (`TravellerRef == ""`) without resolving a traveller; any other empty or stale ref is still 16802.
- Guards, all fail-closed:
  - profiles Seat and AssistedTravel (A07-A09, A15-A19) on a unit without a traveller → `BeneficiaryRequired` (new reason code), never offered and never acceptable;
  - a populated passenger rule group without a traveller → `BeneficiaryRequired` (no match, no fall-through);
  - PTC-bound rates never match without a traveller; usage limits and ages stay unverified rather than inferred (`PriceAssessor`, `QuantityAssessor`, `UnitTimeline` null-guards).
- No dummy passenger anywhere; the candidate's `travellerRefs` is empty and the price is counted once (single unit).
